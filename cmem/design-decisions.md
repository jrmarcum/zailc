# Design Decisions & Invariants

## Decisions made

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-05 | 🌱 **The project exists** (owner; called "Zaig" from 2026-10-05 to 2026-10-08, then renamed, next row): a new project on Zig + Fil-C, AI-assisted, "zag where they zig". zilc stays the stable reference and zailc's test oracle, its cadence unchanged | Owner: keeps zilc maintainable and provable against Zig/LLVM/Fil-C releases without criss-crossing intents, while zailc grows from what zilc proved. Recorded in zilc's `design-decisions.md` the same evening |
| 2026-10-08 | 🏷️ **The name is `zailc` = Zig + AI + Fil-C** (owner). Folder `zailc`, package `.zailc`, binary `zailc-gen`, env prefix `ZAILC_`, work area `~/zailc-work`; GitHub slug `jrmarcum/zailc` when published | Owner: "zaig" has several GitHub projects already; `zaiglang` was liked but "looks too much like ziglang and I don't want to get them mad at just copying them"; `zailc` "is a good compromise and easy to type", and "the punch line states it all in one go: Zig + AI + Fil-C". Measured 2026-10-08 (GitHub search, exact repo-name matches): `zailc` 0; taken: `zaig` 4, `zigai` 3, `zaic` 6, `zeig` 3, `zagi` 10, `zig-ai` 6, `zagai` 2, `zaigen` 2, `zagc` 3, `zygai` 1. The 2026-10-05 history in zilc's cmem keeps the old name with a rename note |
| 2026-10-05 | 📌 **Zig 0.15.2, pinned, until zailc is proven to produce the same as zilc** (owner) | Zig 0.15.2 and Fil-C 0.686 share LLVM 20, so every translated piece can be checked against upstream's output on the same IR. Zig 0.16 emits LLVM 21 IR that Fil-C 0.686 cannot read; moving the line is a separate, later decision |
| 2026-10-08 | 🎯 **Order of work: step 2 before step 3, and inside step 2 the generators first** | The brief (`scope.md`) sizes step 2 as "~250k lines of C to build, almost none to write" and step 3 as 25–35k lines of new Zig. Step 2's generators are the only *writing* in step 2, are deterministic and diffable, and prove the method (port, then prove byte-identity against the oracle) on something small before the pass |
| 2026-10-08 | 🔁 **Where upstream generates a file, zailc's generator reproduces it BYTE-IDENTICALLY, banner included** | The proof is a `cmp`. The generated banner therefore still reads `/* Generated by generate_pizlonated_forwarders.rb */` even though Zig wrote it; changing it would cost the byte-identity check for one line of vanity. Revisit only when zailc stops comparing against Ruby (i.e. when it owns the format) |
| 2026-10-08 | 📥 **Tables that are DATA upstream are imported mechanically, never transcribed** (`tools/gen/import-signatures.ts` → `src/gen/signatures.zig`) | 466 rows typed by hand would carry typos the SHA check would catch only as a whole; an importer makes an upstream change a re-run, and the import is itself reviewable (the tool is 90 lines). The generated file keeps upstream's licence notice because it is derived from upstream's file |
| 2026-10-08 | 🛑 **Nothing built by Fil-C, cosmo, zilc or zailc is ever executed on the Windows host.** All building, testing and running happens inside WSL; the Windows half of an APE only under Wine inside WSL | The development machine runs SentinelOne (EDR). On 2026-10-05 cosmo APE files run as `.exe` from Claude's Windows scratchpad were quarantined and Claude Code was killed (zilc's `workarounds.md`, "Nothing built by Fil-C or cosmo is ever EXECUTED on the Windows host"). Nothing in this work needs the Windows host |
| 2026-10-08 | 📚 **`find_clang_include_dir.rb` is not ported.** `build.zig` passes Zig's own `lib/include` (the clang headers Zig ships) where libpas's Makefile uses the script's result | The script only locates the host clang's resource headers (`stddef.h`); Zig bundles the same headers and knows where they are (`zig env` → `lib_dir`). Porting a 54-line probe of `clang -###` would reintroduce a dependency on a host clang, the opposite of the goal. The brief says the same |
| 2026-10-08 | ⚖️ **Licence: `Apache-2.0 WITH LLVM-exception OR MIT`**, as zilc; ported upstream code keeps its own licence with the notice in every ported file and a ledger row | zilc's `cmem/licensing.md` has the full reasoning (the LLVM exception keeps user binaries free of §4; the MIT arm matches Zig). zailc is a translation project, so the ledger discipline matters more here than in zilc |
| 2026-10-08 | 🔖 **Releases follow binaryang's cadence; zilc keeps its own** (owner: "zilc will follow upstream and maintain its release rules. We will follow the same cadence as binaryang"). Plain semver from `0.1.0`, tags `vX.Y.Z`; patch by default, MINOR for any break (behavioural included); sub-version capped at 9; the version line arms a release, so merge unbumped and bump as its own commit on the owner's go; a patch while `main` holds unreleased work goes from a branch cut from the last tag; `unreleased.md` → `CHANGELOG.md`; release binaries only from CI, never local. Upstream versions are recorded in `upstream.md` / `--version`, not in the number. Full rules and the adaptations: `releasing.md` | Closes the open "version scheme" question. zilc's `<Zig>-<Fil-C>.<release>` names the upstreams it follows; zailc will stop following Fil-C's pass, and binaryang's settled flow (8 of 8 tag-push publishes) already encodes the lessons about irreversible releases |
| 2026-10-08 | 🚀 **A push to `main` releases, as in binaryang** (owner: "when we commit to main we would be also pushing the release like binaryang does. That is how I would like this repository setup also"). `ci.yml` (gates), `auto-tag.yml` (tags a new `build.zig.zon` version and calls `publish.yml`), `publish.yml` (CI-built, attested `zailc-gen` binaries on a GitHub Release); `tools/release/bump.ts`. So `main` only takes `--no-ff` merges, and a bump is its own commit. Departure: auto-tag CALLS publish (`workflow_call`) instead of dispatching it | binaryang's settled pattern, minus its one failing path: a `GITHUB_TOKEN` tag push cannot trigger `push: tags`, and binaryang's dispatch fallback published 0 of 4. ⚠️ With no tag yet, the first push of `main` releases `v0.1.0`. Details: `releasing.md` |
| 2026-10-08 | 🛠️ **Tools in Deno; build logic in `build.zig`; caches and outputs in `~/zailc-work`** | Owner rules carried from zilc (Deno or Bun, never Python or shell; the repo is on exFAT, so Zig's caches go to the Linux work area) |
| 2026-10-08 | 📂 **The Fil-C source tree is an INPUT of `zig build` (`-Dfilc-src`), read-only; nothing of it is vendored, and everything upstream generates in-tree (forwarders, `filc_native.h`, musl's headers) is generated into Zig's cache and reached through include paths** | The tree is the oracle's tree too; writing into it would taint the comparison and upstream's own build. Vendoring 250k lines would turn a translation project into a fork before the translation exists; a pinned tree plus mechanical importers (`signatures.zig`, `libpas_sources.zig`) keeps every upstream change a re-run. Later, `build.zig.zon` can fetch the pinned tree as a package (open question in zilc: whether a hash-checked source package counts as a "third-party download") |
| 2026-10-08 | 🎚️ **Compile settings are upstream's, expressed in Zig's terms**: `x86_64-linux-none` + `x86_64_v2` ↔ `-march=x86-64-v2 -nostdinc` with no libc from Zig; `ReleaseFast` + the explicit `-g -O3 -W -Werror -fno-strict-aliasing`; `pic = true`; `sanitize_c = .off`; `-isystem <zig lib>/include` for `find_clang_include_dir.rb` | Fidelity first: the objects must be the same translation units under the same configuration. Zig's defaults would otherwise add UBSan traps (Debug/ReleaseSafe) and its own libc headers; `-W -Werror` is kept on purpose, and Zig's clang 20.1.2 compiled all 178 objects clean under it |
| 2026-10-08 | 🔬 **Oracle level for compiled objects: the set of DEFINED global symbols per object must equal upstream's; undefined symbols are RATCHETED: each accepted difference is listed in `verify-libpas.ts` `KNOWN_UNDEF_DIFFS` with its `workarounds.md` entry, and a new or vanished one fails** (`verify-libpas.ts`; ratchet added 2026-10-08 at the owner's go, after the day-one review found that any number of undefined differences exited 0) | Bytes cannot match (upstream: Fil-C's clang 20.1.8 via its own driver; zailc: Zig's clang 20.1.2 via Zig's driver), and byte-level checks would measure the compiler, not the port. Equal defined-symbol sets prove the same files, same `#if` configuration and same visibility; behaviour is proven at the next level (link, run, trap; zilc's corpus and Fil-C's suite). One undefined-symbol difference exists today (W-4) |
